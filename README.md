# Traform ACL 자동화 Tool (v1.17.0)

Terraform SG(보안그룹) 접근제어 변경 작업 — **저장소 다운로드 → 브랜치 → 규칙 수정 → Commit/Push → MR → atlantis plan/apply** — 을 웹 화면 하나로 처리하는 도구입니다.
게임환경과 플랫폼환경(GitLab 2곳)을 모두 지원하며, **각자 자기 PC에서 혼자 쓰는 도구**입니다 (기본은 내 PC에서만 접속 가능).

## 처음 받아서 쓰기 (다른 PC 에 배포할 때)
1. 필요: Windows, **Python 3.10 이상**, **git** (명령 프롬프트에서 `python --version`, `git --version` 확인)
2. 받은 zip 을 원하는 폴더에 풀기 → `run.bat` 실행 (필요한 패키지는 처음 한 번만 자동 설치) → 브라우저에서 http://127.0.0.1:8080
3. 화면의 **시작하기** 안내대로: 계정 → GitLab 토큰 → 환경 등록 → 저장소 다운로드. (환경 목록이 들어 있는 zip 을 받았다면 계정과 토큰만 입력하면 됩니다.)
4. 저장소는 따로 지정하지 않으면 프로그램 폴더 안 `repos/` 에 받습니다.

**새 버전으로 바꿀 때**: 새 zip 을 **새 폴더**에 풀고 그 폴더의 `update.bat` 을 실행해 이전 폴더 경로를 알려 주면 `data/`(토큰·환경·이력)와 `repos/` 를 옮겨 줍니다. 이전 폴더는 지우지 않습니다. 환경설정의 **백업 / 복구**로 파일을 받아 두면 더 안전합니다.

**배포하는 쪽**: 화면 왼쪽 **배포** 메뉴에서 저장 위치를 골라 만들거나, `make_dist.bat` 실행 → `dist/` 의 zip 을 전달. 환경 목록까지 같이 주려면 `make_dist.bat --with-config`. 토큰(`data/local.json`)과 작업 이력은 절대 들어가지 않습니다.

## 빠른 시작

```
run.bat              # 의존성 설치 후 서버 실행 → http://127.0.0.1:8080
run_tests.bat        # 서버 자동 테스트 (임시 가짜 저장소 사용)
run_ui_tests.bat     # 화면 자동 테스트 (Node + Edge/Chrome 헤드리스, 임시 가짜 서버 사용)
```

- 포트/호스트: 환경변수 `TF_ACL_PORT`(기본 8080), `TF_ACL_HOST`(기본 127.0.0.1).
- **보호**: 화면/API 는 `localhost`·`127.0.0.1` 주소와 같은 출처(Origin)에서 온 요청만 받습니다 (다른 웹페이지가 내 PC의 이 도구를 몰래 호출하는 것을 막음). 다른 주소로 접속해야 하면 `TF_ACL_ALLOWED_HOSTS=내PC이름` 을 지정하세요.
- 개발 중 코드를 고칠 때는 `TF_ACL_DEV=1` 로 실행하면 코드 변경 시 서버가 자동으로 다시 시작됩니다.
- **서버 코드를 수정/업데이트한 뒤에는 서버를 다시 시작해야 합니다.** 화면 왼쪽 아래의 버전 표시와 `서버 재시작` 링크, 서버가 옛 코드일 때 뜨는 "서버 재시작 필요" 배너의 `지금 재시작` 버튼으로 화면에서 바로 다시 시작할 수 있습니다 (새 콘솔 창이 열리고 화면이 자동 새로고침됩니다).

## 처음 설정 (환경설정 탭)
1. **개인 설정**: 계정(브랜치 접두어/Assignee 기본값), 게임/플랫폼 GitLab 토큰(`api` scope) → `data/local.json` (공유 금지). 게임환경은 clone 에 토큰이 필요 없습니다.
2. **Jira 연동(선택)**: 주소(기본 `https://jira.smilegate.net`)는 `config.json`(공유), **API 키**·인증 방식은 `local.json`(개인). `연결 테스트`는 읽기 전용입니다.
3. **자주 쓰는 소스 프리셋(선택)**: 사무실/VPN 등 자주 쓰는 IP 를 이름과 함께 등록 → 마법사·일괄 추가·IP 삭제에서 불러오면 이름이 출발지 정보로 쓰입니다.
4. **유형별 기본값**: GitLab URL, 프로젝트 경로(플랫폼 `cloudcenter/cloud-multiverse`), 대상 브랜치, repo 로컬 경로.
5. **환경 목록**: 환경 직접 추가 또는 행의 **환경 검색**(저장소 안의 `sg_rule` 폴더를 찾아 자동 등록). 열 머리글의 깔때기로 필터링. **환경 점검/정리**로 중복 ID·폴더 없는 환경·연결이 끊긴 메타를 정리합니다.

## 엑셀 연동 (선택, ACL 적용내역 기록)
- 환경설정 > **엑셀 연동**에서 작성자 이름, 엑셀 폴더(폴더 선택), 엑셀 파일, 시트(`ACL 적용내역`)를 지정합니다.
- 작업 탭의 **엑셀 기록** 또는 apply 완료 직후 뜨는 확인 창에서, 이번 작업의 변경 규칙을 한 건당 한 줄로 확인/수정한 뒤 시트의 C열 마지막 내용 아래에 기록합니다. 엑셀이 열려 있으면 열려 있는 엑셀에 직접 기록하고(PowerShell COM), 닫혀 있으면 파일에 기록하며, 기록 전 파일은 `data/excel_backup` 에 백업됩니다.

## AWS 연동 (선택, 메타 데이터 가져오기)
- 필요: **AWS CLI v2**, `aws configure sso` 로 만든 프로필(`~/.aws/config`). 메타 데이터 화면 → **AWS 에서 가져오기** → 프로필/리전 선택 → 조회 결과 확인 → 반영.
- 프로필은 **자동으로 찾습니다**: 로그인된 계정들에서 이 환경의 SG 가 보이는 계정을 골라 미리 선택합니다. SG 를 쓰는 리소스의 IP 는 별명에 `10.0.0.1, 10.0.0.2` 형태로 넣을 수 있습니다.
- 프로필은 이름/계정 ID 로 검색할 수 있고, 리전은 `apne1`, `ape1` 같은 짧은 코드도 받습니다. 회사 보안 프로그램(SSL 검사) 때문에 인증서 오류가 나면 이 PC 가 신뢰하는 인증서로 자동 재시도합니다 (`data/aws_ca_bundle.pem`).
- AWS 에는 **조회 명령만** 보내며 아무것도 바꾸지 않습니다. 로그인이 만료되면 화면의 안내에 따라 `로그인 창 열기` → 브라우저에서 승인하면 자동으로 이어집니다. `Access Denied` 는 권한 요청이 필요하다는 뜻입니다.

## 화면 구성
| 메뉴 | 설명 |
|---|---|
| **작업** | 1.저장소 다운로드 → **⚡ 빠른 작업(마법사)** → 2.브랜치 준비 → 3.Commit/Push(+변경 요약 보고서) → 4.MR 생성 → 5.Atlantis → **작업 이력** |
| **접근제어** | SG 목록/규칙 조회·추가·수정·삭제, 선택 복사, **선택 삭제**, 여러 IP 일괄 추가, 다른 SG(같은 저장소의 다른 환경 포함)에 적용, **IP로 규칙 삭제**, CSV 업로드(미리보기)/다운로드, 변경 내용 보기 |
| **메타 데이터** | 환경 정보(Subnet name, VPC ID, IPv4 CIDR, NAT IP)와 SG별 별명/SG ID/태그 — CSV 업로드/다운로드 |
| **환경설정** | 개인 설정, Jira, 프리셋, 유형별 기본값, 환경 목록 |

상단 **유형 → 종류 → 환경(→ 리전/티어)** 드롭다운과 **통합 검색**(`/` 키): IP·CIDR(대역 포함)·도메인·태그·SG ID·SG명·서브넷 정보를 찾아 결과를 고르면 환경이 자동으로 선택됩니다. 검색 결과 아래 `사용처 보고서`는 그 검색어가 쓰이는 모든 규칙을 표/CSV/마크다운으로 보여줍니다 (SG 이름·ID 로 검색하면 그 SG를 소스로 참조하는 규칙도 포함).

## 작업 순서와 안전장치
1. **저장소 다운로드**: 없으면 clone, 있으면 fetch(파일은 건드리지 않음). 기존 폴더 처리: 유지 / 백업 후 새로 받기 / 삭제 후 새로 받기.
2. **브랜치 준비**: 대상 브랜치 최신화 후 `계정/YYMMDD_티켓` 브랜치 생성 (중복 시 `_01`, `_02`…).
3. **규칙 수정** (접근제어 탭)
   - `main`/기본 브랜치/detached 상태에서는 서버가 수정을 막습니다 (배너에서 이 세션 한정 허용 가능).
   - 저장 전 검증: 호스트 비트 CIDR·포트 범위·빈 설명 등은 **저장 불가**, 인바운드 `0.0.0.0/0`·광범위 대역·전체 포트·**넓은 대역에 연 관리 포트(22/3389/5985/5986)** 는 **확인 후 저장**(기준과 **허용 예외**는 환경설정의 **정책 규칙**에서 바꿈), 중복·**다른 규칙 범위에 포함되는 겹침**·설명 명명 규칙 불일치·**이미 지난 만료일(`만료:2026-12-31`)** 은 **경고**.
   - Commit 전 변경은 음영으로 표시됩니다. 저장할 때 기존 파일의 줄바꿈(CRLF/LF)·마지막 개행·BOM 을 그대로 유지합니다.
4. **Commit & Push**: 변경 diff 확인 창에서 **대상 브랜치가 앞서 있는지**, **같은 SG 파일이 서로 바뀌었는지(충돌 가능, 확인란 필요)**, 원격 작업 브랜치가 앞서 있는지를 함께 알려줍니다. **SG 폴더(sg_rule)의 파일만** add/commit 합니다.
5. **MR 생성**: 같은 브랜치로 열린 MR 이 있으면 새로 만들지 않고 연결(중복 방지). 게임/플랫폼 전용 템플릿, MR Type `SG 정책 추가/변경/삭제` 고정, Assignees/Reviewers 선택.
6. **Atlantis**: `atlantis plan -d <경로>` 후 결과를 색(삭제 빨강/추가 초록/변경 주황)으로 표시. **apply 는 같은 MR 커밋에서 성공한 plan 이 있어야** 하며, 삭제·교체가 포함되면 한 번 더 확인합니다. 실패하면 원인(브랜치 없음/인증/잠금/Terraform 오류/시간 초과)과 **다음 행동**을 안내하고 `plan 다시 실행`, `Commit/Push 로 이동`, `atlantis unlock`(확인 필수) 버튼을 제공합니다. 응답 대기 중 새로고침해도 이어서 조회합니다.
7. **빠른 작업(마법사)**: 작업 종류(규칙 추가 / 규칙 삭제(IP 기준) / 새 SG 만들고 규칙 추가) + 티켓 + 대상 SG(여러 개) + IP/포트 → 전체 내용을 한 번 확인 → 브랜치 → 규칙 변경 → Commit/Push → MR → (선택) plan. **apply 는 자동으로 하지 않습니다.** 작업 이력의 `마법사로 복제`로 이전 설정을 다시 불러올 수 있습니다.
8. **영향 분석**: `변경 요약 보고서`(3번 카드)는 이번 브랜치의 추가/삭제 규칙·영향받는 SG·위험 규칙을 표로 보여주고, MR/Jira 에 붙일 마크다운 복사·Jira 코멘트를 지원합니다.
9. **작업 이력**: 모든 단계의 결과가 서버(`data/history.json`)에 저장됩니다.

> 이 도구는 운영 저장소를 변경할 수 있습니다. 테스트/개발 시 실제 저장소·GitLab 에는 읽기 작업만 하고, 생성·변경은 임시 가짜 저장소에서 확인하세요.

## 점검 보고서 (읽기 전용)
- **규칙 점검 보고서**(접근제어 탭 왼쪽 위): **만료 규칙**(설명의 `만료:YYYY-MM-DD`), **정리 제안**(중복·포함), **접근 경로(IP)**(조회 IP → 포트 → 환경 토폴로지 그림, 노드를 누르면 표가 걸러짐) — 모든 환경을 대상으로 하며 파일을 바꾸지 않습니다. CSV 로 받을 수 있습니다. 보고서 창은 넓게 열리고 오른쪽 아래 모서리를 끌어 크기를 바꿀 수 있습니다(바꾼 크기는 기억, 모서리를 더블클릭하면 기본 크기).
- **규칙 점검 보고서의 탭(v1.13)**: 만료 규칙 / 정리 제안(체크한 규칙을 작업 브랜치에서 삭제) / 접근 경로(IP, **SG 경유** 옵션) / **SG 관계**(SG 를 소스로 지정한 참조 그림) / **기준 점검**(환경별 점수와 등급) / **티켓 찾기**(티켓 번호가 들어간 규칙·브랜치·MR).
- **위험 규칙 승인 사유**: 위험 확인 창에서 사유를 적어야 진행되고, `data/risk_approvals.json` 에 남아 변경 기록 파일과 MR 본문에 붙습니다.
- **이미 열려 있음 점검**: 규칙을 넣을 때 같은 SG 의 더 넓은 규칙이 이미 허용하면 확인을 받고, 같은 환경의 다른 SG 에 열려 있으면 참고로 알려 줍니다.
- **서비스 사전**(환경설정): 이름 붙인 프로토콜·포트를 빠른 작업에서 고릅니다. IP 입력칸에는 프리셋을 `@프리셋이름` 으로 쓸 수 있습니다.
- **AWS 비교 이력**: 비교 결과를 `data/compare_history.json` 에 남겨 지난번보다 새로 생긴 차이와 해소된 차이를 알려 줍니다.
- **Jira 티켓으로 채우기**(v1.14): 빠른 작업의 **Jira 티켓에서 채우기**(또는 **채우고 실행 확인**)가 티켓을 읽기만 해서 출발지 IP·포트·프로토콜·방향·대상 SG 후보를 채워 줍니다. 읽은 값은 확인·수정한 뒤에 쓰이고, 실행은 기존 확인 창을 거쳐 브랜치 → 규칙 추가 → Push → MR → plan 까지 진행합니다(apply 는 직접). 포트는 `443, 8080-8090` 처럼 여러 개를 적을 수 있습니다.
- **도메인 조회**(v1.14): 통합 검색에 도메인을 넣으면 나오는 버튼으로 DNS 결과와 메타 데이터(SG 태그·별명)를 비교하고, 메타 데이터가 있는 SG 의 태그에 `domain:도메인` 을 추가합니다.
- **표준 요청 양식 읽기**(v1.15): 티켓 설명의 표(no / 구분 / Project / Source IP / Source Env / Destination IP / Destination Env / Service Port / 용도 / 사용 기간 / 비고)를 읽어, 같은 (구분·목적지·프로토콜·포트)인 행의 출발지 IP 를 한 묶음으로 모읍니다. 묶음이 여러 개면 고른 한 묶음씩 채우고, 구분이 '삭제'면 삭제 작업으로 채웁니다. **요청 양식** 버튼은 요청자가 붙여 넣을 표를 복사해 줍니다.
- **apply 까지 진행(선택)**(v1.15): 빠른 작업의 체크박스를 켜면 plan 이 이상 없을 때(삭제·교체 0건, 변경이 대상 SG 안에서만, 위험 규칙 승인 없음) apply 까지 자동으로 진행하고, 아니면 멈춰서 알려 줍니다. 끄면 apply 는 직접 합니다. plan 결과에는 바뀌는 리소스와 검사 항목이 함께 보입니다.
- **Jira 완료 처리**(v1.15): apply 가 끝나면 코멘트(MR·plan 요약·apply 시각)를 남기고 상태를 전환합니다. 처음에는 확인 창에서 전환을 고르고, 고른 이름은 기억해 다음부터는 빠른 작업에서 묻지 않고 실행합니다.
- **여러 티켓 일괄**(v1.15): 티켓 번호 여러 개를 읽어 (티켓 × 묶음) 목록에서 고른 것을 차례로 처리합니다(건마다 확인).
- **담당자 / 감사 보고서**(v1.15): 메타 데이터 화면에 SG별 담당자를 적으면 만료·정리 제안·기준 점검 보고서에 담당자 열과 필터가 생기고, '담당자별' 탭에서 현황을 봅니다. '감사 보고서' 탭은 기간별 변경 이력·위험 규칙 승인 사유·만료·정리 제안·기준 점검·담당자별을 Excel(.xlsx) 한 파일로 내려받습니다.
- **화면 보강**(v1.16): 화면 아래 **진행 패널**(빠른 작업 단계와 Atlantis 응답 대기를 어느 탭에서나 확인), 실행 확인 창 **요약 칩**과 접는 진행 단계, 빠른 작업 카드의 **시작하기/진행 옵션** 정리, 오류 알림 **복사·닫기·Esc**, 위험한 작업 확인 버튼 **빨간색**(처음 포커스는 취소), 글자 입력칸 **Enter 확인**, 자동으로 뜨는 창의 **대기열**, 보고서 표 **정렬·찾기·더 보기**, 사이드바의 **화면 색상(자동/밝게/어둡게)·글자 크기**, 작업 탭 **처음 안내**.
- **한 화면에서 끝내기**(v1.17): 모든 탭 위의 **작업 바**(브랜치·변경 수·되돌리기·Commit/Push·MR·plan), 진행 패널의 **plan 결과와 apply 버튼**, 오른쪽 **슬라이드 패널**(빠른 작업, SG 규칙 보기·삭제·만료 연장·메타 데이터 수정), 보고서 행의 **삭제·연장**과 SG 링크, 검색 결과 **미리보기**, 오류 알림의 **여기서 설정** 버튼(Jira·GitLab 토큰·저장소 경로·AWS 로그인·브랜치 준비), **Ctrl+K 명령 팔레트**, 탭·환경·SG 를 담은 **주소(#)와 뒤로가기**, 탭별 스크롤·보고서 탭 기억, **최근 칩**.
- **변경 기록 파일**: 작업 탭 > 변경 요약 보고서 > 변경 기록 파일 저장(.md). MR 본문에는 자동 점검 결과(위험·경고)가 붙습니다.

## 데이터 파일 (`data/`)
| 파일 | 내용 | 공유 |
|---|---|---|
| `config.json` | 환경 목록·경로·유형별 기본값·Jira 주소·프리셋 | 공유 가능 |
| `meta.json` | SG ID/별명/태그, 환경 정보(서브넷/VPC/NAT) — 환경 ID 에 연결되며 환경 경로 스냅샷(`_sg_dir`)을 함께 기록 | 공유 가능 |
| `local.json` | 계정, GitLab/Jira 토큰 | **공유 금지** |
| `history.json`, `plans.json` | 작업 이력, 마지막 plan 결과 기록 | 런타임 (git 제외) |
| `app.log` | 서버 오류 기록 (토큰 가림, 1MB 초과 시 교체) | 런타임 (git 제외) |
| `undo.json` | 되돌리기용 변경 전 내용 (Commit/Push 하면 비워짐) | 런타임 (git 제외) |
| `backup/` | 환경 정리 시 자동 백업 (최근 20개 유지) | 런타임 (git 제외) |

환경 ID 는 한 번 만들어지면 바뀌지 않습니다 (이름·경로를 수정해도 메타 데이터가 유지됨). 환경이 삭제되거나 ID 가 바뀐 메타는 `환경 점검/정리`가 같은 경로의 환경으로 다시 연결하거나 목록으로 알려줍니다.

## 파일 규칙
- 플랫폼: `[리소스].json` (`{ingress, egress}`, 들여쓰기 4칸, 프로토콜 소문자, IP 규칙의 `security_groups` 는 `null`)
- 게임: `[접두어][리소스]-sg-ingress-rules.json` / `-egress-rules.json` (배열, `cidr_blocks` 한 줄, 프로토콜 대문자, `security_groups` 는 `"null"`)
- 규칙 설명: `tf_YYMMDD_티켓_출발지 to 목적지 Connection` (설명 자동생성: 출발지는 태그/SG ID/프리셋으로 자동 인식, 목적지는 현재 SG)

## 문제 해결
| 증상 | 조치 |
|---|---|
| "서버 재시작 필요" 배너 / 404 | 서버가 옛 코드입니다. 배너의 `지금 재시작` (또는 run.bat 창 종료 후 다시 실행) |
| GitLab 인증 실패 안내 | API 토큰 만료/권한 없음 — 환경설정에서 계정과 토큰 확인 (게임은 clone 에 토큰 불필요) |
| 서버에 연결하지 못함 | 네트워크/VPN 확인. SSL 오류면 환경설정의 SSL 인증서 검증 옵션 확인 |
| "작업 브랜치가 아닙니다" | 작업 탭에서 `브랜치 준비` 후 수정 |
| plan 실패 | 작업 이력의 안내(원인/다음 행동)와 `plan 다시 실행`, 잠금이면 `atlantis unlock` |
| 환경이 이상하게 열림/메타가 안 보임 | 환경설정 → `환경 점검/정리` |
| 다른 주소로 접속이 거부됨(403) | `TF_ACL_ALLOWED_HOSTS` 설정 |

## 테스트
- `python -m unittest discover -s tests -v` — SG 파일 형식, 검증, 검색, CSV 미리보기, git 범위/브랜치 가드, push 전 최신 여부, Atlantis 판정·실패 분류·apply 검사, 이력 API, MR 설명/중복 방지, 일괄 삭제, 보고서, 환경 정리/고아 메타, Host/Origin 검사 등.
- `node tests/ui/run_ui_tests.js` — 브라우저(Edge/Chrome 헤드리스)로 화면을 실제로 눌러 보는 자동 테스트 (마법사 전 과정, 확인 모달, 일괄 삭제/적용, MR 중복 방지, plan 실패 안내, 환경 정리, 프리셋, 통합 검색 등). 외부 패키지가 필요 없습니다. 브라우저 경로를 바꾸려면 환경변수 `BROWSER`.
- 모든 테스트는 임시 폴더의 가짜 저장소와 가짜 GitLab/Jira 응답만 사용하며 실제 시스템과 실제 `data/` 를 건드리지 않습니다.
